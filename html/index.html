Goblin Skiff

Goblin Skiff

Goblin Skiff is a fork of Mosh, optimized for bandwidth-constrained links. Skiff keeps Mosh's roaming and predictive typing, and adds UDP jump relays for sessions where the client cannot reach the destination directly over UDP. It also adds zstd-22 compression, directional bandwidth pacing, repairable file transfers, and modern terminal graphics. The changes target very low-bandwidth satellite, radio, and metered links: fewer unnecessary bytes, with input and screen updates ahead of background copies.

01 / Artifacts

What changed, in the source.

Each entry starts with the implementation artifact, then states the reason for the change and the practical effect it is intended to have.

A01

Authenticated UDP jump relays

src/frontend/relay-server.cc src/network/relay.cc UDP_RELAY.md

Changed

-J and SSH ProxyJump routes now carry the Mosh UDP session through up to four jump-host servers. SSH configures each fixed-destination relay, then exits.

Why

Jumping only for login does not help when the client cannot reach the destination over UDP. Adjacent hosts can relay that traffic while the terminal session remains encrypted end to end.

Why it matters

Each hop has an independent key, replay protection and authenticated client roaming. Framing adds 24 bytes per hop, or 36 with FIPS crypto, budgeted in both directions. Relays reuse Mosh's idle pings and expire after a configurable period of client silence.

A02

Negotiated zstd-22 state compression

src/network/compressor.cc src/network/transportsender-impl.h transportinstruction.proto

Changed

Once both peers advertise zstd, every serialized state update uses zstd level 22. Initial packets stay with zlib for negotiation.

Why

Screen updates are small but frequent, and satellite bandwidth is expensive. State compression is a core part of the link strategy.

Why it matters

There is no size threshold, zlib comparison, or codec-level tuning. After negotiation, the state codec is always zstd-22.

A03

Session-specific state dictionaries

src/network/statesamples.cc mosh-compile-dictionary.cc

Changed

State updates can be sampled, compiled into a zstd dictionary, and supplied during session setup.

Why

Terminal applications repeat structures, prompts, status lines, and escape sequences that a trained dictionary can represent compactly.

Why it matters

Dictionary compression activates only when both peers advertise the same dictionary ID, keeping the choice explicit and verifiable.

A04

Directional pacing and stream priorities

src/frontend/streamforward.cc src/network/linkbudget.h

Changed

Each direction estimates its own delivery budget. A session-wide pacer covers terminal, forwarding and FEC traffic; -L/-R/-D/-A/-X streams have separate priorities.

Why

Uplink and downlink capacity can differ substantially. A file copy or tunnel must not fill the queue needed by an interactive shell.

Why it matters

Clean, busy links ramp up quickly; loss or a slower path cuts the budget. The menu shows traffic, send budgets and outgoing loss. Estimates are not guaranteed link capacity.

A05

File browser, recursive copies and delta sync

src/moshcp/ src/frontend/filetransfer.cc src/frontend/directory.cc

Changed

A persistent two-pane browser queues file or directory copies. Matching files use librsync signatures and deltas, with zstd-22 and background FEC in both directions.

Why

Resending an existing file wastes bandwidth. Shipping a complete large-directory listing wastes it before the copy even starts.

Why it matters

Helpers sort names locally and send bounded metadata windows. Live updates, queues and progress stay responsive over loss; SHA-256 checks reconstructed files before replacement.

A06

Clipboard lanes and consent-aware downloads

src/frontend/mimeclipboard.cc GOBLIN_DOWNLOAD_PROTOCOL.md

Changed

OSC 52 and MIME-aware OSC 5522 stay outside screen state. Goblin inline downloads use binary zstd-22/FEC and forward to a supporting Goblin parent, then Kitty, or a local save prompt.

Why

A paste is interactive; a large unsolicited remote blob is not. Applications also need a way to offer a file without silently writing into Downloads.

Why it matters

Local-to-remote and plain-text clipboard data stay fast. Remote non-text writes above a configurable 64 KiB cutoff go in the background. Local download saves require approval and never overwrite.

A07

Retained Kitty and sixel image state

src/terminal/kittygraphics.cc src/statesync/kitty.cc SIXEL_STATE.md

Changed

Static Kitty and sixel images use WebP or negotiated palette/DjVu state plus placement deltas. Images with up to 16 colors can use lossless DjVu bitplanes. Kitty uploads accept inline, file, temporary-file and shared-memory media on the server.

Why

Pixel data is expensive. Moving text or an existing image should not require retransmitting all its pixels.

Why it matters

Encoding stays lossless by default, with WebP fallback for older peers. --lossy=0..100 opts into lossy WebP; --djvu-lossy separately enables lossy two-color DjVu. Sixel stays sixel on a capable client, with conversion on Kitty-only clients. Tests cover 5,120-pixel-wide images.

A08

Geometry, keyboard events and sized text

scripts/mosh.pl src/frontend/mosh-server.cc src/terminal/sizedtext.cc graphics-integration.py

Changed

The remote session receives the local TERM and attachment geometry. Cell-size queries, Kitty keyboard events and OSC 66 text sizing have explicit handling.

Why

Terminal identity alone does not describe current cell pixels or enabled protocols. Resizing must update geometry without making it persistent screen content.

Why it matters

Applications can size images and position the cursor below them. Configured Alt events pass through; unsupported sized text falls back to ordinary text. Remote terminfo is still required.

A09

Prefixed packages and an explicit FEC policy

GOBLIN_PREFIX_NOTES.md configure.ac packaging/check-prebuilt-fec.sh THIRD_PARTY.md

Changed

Programs and man pages use the goblin- prefix. Debian/Ubuntu, RPM and Homebrew recipes ship built-in Reed–Solomon FEC and reject RaptorQ-enabled binaries.

Why

The fork needs to coexist with stock Mosh, preserve its GPL-3.0-or-later license, and keep RaptorQ out of distributed binary packages.

Why it matters

Stock mosh remains separate. RaptorQ is off even in ordinary source builds; enabling it requires explicit custom compilation and review of its patent terms.

A10

Native scrollback and tmux control mode

src/terminal/terminaldisplay.cc src/statesync/tmux.cc

Changed

Native scrolling uses the primary screen by default. Optional --tmux-control transports tmux -CC as reliable ordered bytes.

Why

Earlier output and the local startup mascot should scroll into history. A terminal's native tmux tabs need the control protocol, not a rendered screen diff.

Why it matters

Received rows can stay in local history. Skipped intermediate output cannot be recovered. tmux control mode preserves protocol bytes but can cost more bandwidth.

A11

Lower redraw rate and idle backoff

src/network/transportsender.h src/network/network.cc

Changed

Sustained screen updates run at 10–4 frames per second according to RTT. Negotiated idle pings back off from 15 seconds through 30, 60, 120, 240, 480 and 900 seconds.

Why

An unattended terminal should not keep paying for frequent state heartbeats. Fast redraws also consume bandwidth even when newer frames replace older ones.

Why it matters

The first update after idle still leaves promptly. Activity resets the ping interval; compact authenticated pings avoid screen serialization. Long idle intervals can let NAT mappings expire.

A12

Fail-closed FIPS-provider crypto option

src/crypto/fips_crypto.cc src/tests/fips-crypto.cc

Changed

--fips-crypto requires an installed OpenSSL 3 FIPS provider for AES-128-GCM, HKDF-SHA-256 and random generation. Setup fails if either endpoint cannot use it.

Why

A future FIPS-oriented deployment needs an explicit alternative to the normal OCB transport, without silently falling back to it.

Why it matters

This is a deployment building block, not FIPS certification. It adds 12 IV bytes per datagram; the validated module, SSH bootstrap and operating environment remain deployment responsibilities.

Userspace proxy networking

Setup and limitations

Smaller palette images

Negotiated palette/DjVu transport targets small-color images. Lossless remains the default; WebP quality and two-color DjVu lossiness have separate opt-in flags. Builds now require DjVuLibre and its encoder tools.

The graphics row compares carrying a remote application's graphics protocol to the local terminal, not whether the connection can run inside Kitty. Goblin Skiff interprets supported static graphics, synchronizes image and placement state, then re-emits graphics client-side; it is not byte-for-byte passthrough. Sixel is re-emitted as sixel when supported locally, or converted client-side to Kitty on a Kitty-only terminal. SSH and Eternal Terminal carry the inline protocol bytes without interpreting the images. Display still requires a capable local terminal; byte passthrough alone does not resolve a remote filename or shared-memory reference locally. Native tmux integration also needs a supporting local terminal. None of the rows claims that Goblin Skiff implements every SSH feature or every Kitty extension.

The jump-host row compares the session's data path, not just SSH login. Goblin Skiff no longer needs direct client-to-destination UDP reachability when using its relays; UDP must pass between adjacent hops. The client, every jump and the destination need updated Goblin binaries. Session encryption remains end to end; each hop adds its own authentication. This is not arbitrary UDP port forwarding: -L/-R and SOCKS5 -D carry TCP streams. The new source option --socks5-proxy uses an external proxy's UDP ASSOCIATE support for the Mosh session itself. Idle relays expire after a configurable period of client silence (24 hours by default). Relay setup and wire format.

  1. Mosh's transport design, scrollback FAQ, and upstream issues for Kitty graphics, sixel and forwarding. Roaming and predictive typing are upstream Mosh features, not new inventions of this branch.
  2. OpenSSH ssh(1) and sftp(1) document forwarding, compression, jump hosts, PTYs and file transfer. Graphics/history entries describe byte-stream behavior, not an OpenSSH graphics renderer.
  3. Eternal Terminal usage and transport design describe reconnect/replay, TCP forwarding, jump hosts and tmux control mode. Passthrough entries follow from its byte-stream design.
  4. autossh features and README describe monitoring and restarting SSH. It is included as a practical related utility, not as another Mosh protocol implementation.

03 / Wire behavior

Which traffic goes first.

Compression reduces the amount of data. Scheduling determines which data gets the scarce send opportunity when several features are active at once.

Traffic Class Send rule
Terminal state + input primary Scheduled before forwarded streams and bulk transfer.
Directory requests control Reliable bounded metadata on reserved stream 0; filesystem work runs in a separate helper.
Interactive clipboard fast Separate authenticated FEC lane; local-to-remote and plain-text data do not wait behind background copies.
SSH agent + X11 medium Shares a medium-priority token bucket.
TCP + SOCKS low Uses a separate low-priority token bucket.
Files + large remote blobs background Uses remaining paced opportunities. Due foreground work runs first; a screen waiting for its next frame timer need not stall a copy.

Why this matters

Satellite and radio paths may provide usable connectivity with a small or variable capacity budget. A feature is not link-aware merely because it uses compression.

Upload and download budgets are estimated separately. A manual transfer-rate ceiling still applies when configured; goblin-skiffcp --rate=0 removes its own ceiling, not the session-wide pacer. Sparse traffic cannot measure unused link capacity.

05 / Inspect

Inspect or build the source.

The prefixed binaries are intentional: they let this patch set live beside an ordinary Mosh installation. See the README and packaging recipes for build dependencies. The package setup pages are the simpler installation route.

shell low-bandwidth-mosh 
$ git clone --branch low-bandwidth-mosh --single-branch \
    https://github.com/adamdeprince/goblin-skiff.git
$ cd goblin-skiff
$ ./autogen.sh
$ ./configure --with-zstd --with-librsync \
    --without-libraptorq
$ make
$ make check
$ sudo make install

# Run the prefixed client.
$ goblin-skiff user@host

06 / Limits

Evaluation notes.

The branch is a working patch series, not an upstream Mosh release.

Endpoints and jump hosts

Enhanced features require compatible client and server builds. Starting with source version 1.4.0-goblin20260915.1, compatible releases share Goblin protocol 1 and negotiate optional features. UDP jump routes also need an updated Goblin server on every jump, with UDP reachability between adjacent hops. SSH-only jump hosts do not relay Mosh UDP.

Four-hop transfer ramp-up

In four-hop release stress checks with one in seven datagrams dropped plus reordering, first-file completion took up to 141 seconds while keyboard input remained live. Conservative pacing plus relay overhead still needs tuning; the file-completion test window is 300 seconds.

Sensitive samples

State sample logs contain uncompressed terminal updates and may include commands, output, or other sensitive terminal contents.

Not implemented yet

Session audio, live forwarding edits in the popup, arbitrary UDP port forwarding and automatic drag-and-drop uploads remain outside the implemented feature list. Founsure has not been added.

Open the file menu with Ctrl-^, release, then 0 (usually Ctrl-6 in Kitty). Enter starts a copy without leaving the browser; Tab or Shift-Tab swaps panes, Left goes up, and Right enters a directory. Hiding the menu preserves its state; ending the session does not. Large directory workers and transfer queues have bounds, but a slow filesystem can still delay its own results.
